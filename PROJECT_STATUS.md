## Project overview

**Vantyx** is a gradual-typing programming language implemented in Rust. It targets Python-like ergonomics with Rust-like safety and a real native compilation path. Repository codename: RustZ.

- Language: Vantyx
- Repository: https://github.com/zeiad6/vantyx (public, MIT; renamed from `zeiad6/auren`)
- File extension: `.vtx`
- CLI: `vantyx`
- Implementation: Rust 1.100.0, 2024 edition, zero third-party dependencies
- Version: 0.1.0 (pre-release)
- Maturity: **functional prototype** — front end, interpreter, typed IR, and a native C backend for a statically typed subset that now includes closed enums, exhaustive `match`, scalar literal patterns, nested payload patterns in the interpreter and native backend, top-level or-patterns in the interpreter and native backend, integer range patterns in the interpreter and native backend, match guards, statement-position result-enum `?` propagation, `range(...)` list values in both engines, and basic UTF-8 file I/O; plus an offline, dependency-free AI host foundation and `vantyx ai` CLI

## Implemented and verified

Every item below is exercised by the test suite or was manually verified through the CLI.

### Language front end
- Indentation-aware lexer with `INDENT`/`DEDENT`, tab rejection, CRLF handling, blank/comment-only lines, bracket continuation.
- Integer literals (decimal, `0x`, `0b`, `0o`, `_` separators), floats with exponents, strings with escapes and `{expr}` interpolation.
- Recursive-descent parser with Pratt expressions, single-line suites, struct constructors, enum declarations, match statements/expressions, and expression/block/type depth guards.
- Spans on every token and AST node; per-file source registry; non-panicking error recovery in lexer and parser.
- File-based modules (T-013): `import "lib/math.vtx"` and `from "lib/math.vtx" import add, Point`; paths resolve relative to the importing file and must stay under the entry file's directory; every file is parsed once; declarations flatten into one global scope; cycles, missing files, unknown selected names, path escapes, non-entry statements, and non-entry `main` produce `E0501`–`E0512`; imports are rejected in `run -` and the REPL (`E0510`).
- Diagnostics with `E0xxx`/`W0001` codes, source line, caret, notes, and help text.
- Static lints (T-073/T-085, ADR-0037): `vantyx lint <file>` compiles with the normal pipeline and reports `L0001` unused binding, `L0002` `var` never reassigned, `L0003` unreachable statement after a direct `return`/`break`/`continue`, and `L0004` unused parameter; names starting with `_`, loop variables, and match bindings are ignored; findings are warnings and exit `0`, compile errors exit `1`; there is no suppression, configuration, machine-readable output, or automatic fix yet.
- Reachability-aware return checking (T-074, ADR-0037): `E0309` ignores dead code after a reachable `return` or after an `if`/`else`/`match` whose every branch returns; a reachable `break`/`continue` still stops the path.

### Type system
- Gradual typing: unannotated parameters and bindings are `Any`; annotated boundaries are checked statically where possible and at runtime otherwise.
- `let` immutability and `var` mutability; duplicate-declaration detection; shadowing allowed only in inner scopes.
- Function arity, parameter types, return-path analysis, and annotated return checks.
- Nominal structs with typed fields and named or positional constructors.
- Nominal enums (T-014): payload variants, globally unique variant constructors, pattern bindings, static exhaustiveness (`E0316`), unreachable-arm warnings (`W0003`), and `Any`-match warning (`W0004`).
- Scalar literal patterns (T-032): `Int` (including negative), `Str`, and `Bool` literals in `match`; `Bool` exhaustiveness over both values; `Int`/`Str` open-ended matches require `_`; duplicate literals warn (`W0003`); literal/variant type mismatches are `E0315`/`E0301`.
- Match guards (T-033): `pattern if <expr>` in match statements and expressions; guards are type-checked as `Bool` (`E0301`; dynamic non-`Bool` is `R0005`), see payload bindings, run in source order, and never contribute exhaustiveness coverage. Repeated guarded arms are not reported as unreachable.
- Top-level or-patterns (T-047): `Circle(size) | Square(size)` in both match forms. Every alternative must bind the same names with the same types (`E0317`); the arm receives one binding set. Unguarded alternatives contribute coverage; guarded or-patterns contribute none. `|` is not an expression operator.
- Nested payload patterns (T-048/T-049, ADR-0019/ADR-0020): `Node(Leaf(value), _)` in both match forms, up to 64 levels. Bindings from every level join one immutable arm scope; duplicates are `E0202`. Exhaustiveness uses a recursive constructor matrix, so `Leaf(value)` + `Node(Leaf(left), _)` + `Node(_, _)` is accepted and `Node(Leaf(value), _)` alone is `E0316`. Native lowering emits short-circuit tag/literal tests and declares bindings from absolute payload paths. Payload or-patterns and tuple patterns remain unsupported.
- No implicit numeric coercion; `/` produces `Float`, `//` floors toward negative infinity.
- Entry-point rules: top-level statements execute; otherwise zero-argument `fn main()` is called; warning `W0001` when both exist.

### Runtime (interpreter)
- Values: `Unit`, `Int` (i64), `Float` (f64), `Bool`, `Str`, `List`, `Map` (insertion-ordered), nominal `Struct`, nominal `Enum`.
- Module loading (T-013): imported functions, structs, and enums execute with the same semantics as declarations in the entry file; top-level statements remain entry-file-only; recursively imported declarations are deduplicated and every source span retains its original file.
- Enum construction, immutable payload slots, structural equality/display, `type` reporting the enum name, pattern matching, and `R0014` when no dynamic arm matches (T-014).
- Scalar literal matching on `Int`, `Str`, and `Bool` in both match statements and expressions, including negative integers (T-032).
- Guard evaluation after pattern bindings, with false guards continuing to the next arm and guard errors/scope cleanup handled correctly (T-033).
- Top-level or-pattern matching tries alternatives in order and installs the shared binding set in the arm scope (T-047). Nested payload matching recurses into payload values and merges bindings from every level (T-048).
- Checked arithmetic with overflow detection, division-by-zero checks, bounds checks, missing-key errors.
- Reference semantics for lists, maps, and structs (`Rc<RefCell<...>>`).
- `if`/`elif`/`else`, `while`, `for` over lists, strings, and map keys; `break`/`continue`/`return`.
- Recursion with `MAX_CALL_DEPTH = 256` and evaluation-depth guard; interpreter runs on a dedicated 16 MiB stack.
- Runtime errors `R0001`–`R0017` with spans and stack traces; output failures become `R0013`; dynamic match failures are `R0014`; file, directory, rename/copy, and recursive-copy I/O failures are `R0015`; invalid builtin argument values are `R0016`; `R0017` is a defensive error for a `?` operand that is not a two-variant one-field enum or is used outside a supported statement position (the checker normally rejects these first).
- Builtins: `print`, `len`, `range`, `push`, `pop`, `contains`, `keys`, `values`, `str`, `int`, `float`, `bool`, `type`, `abs`, `min`, `max`, `sqrt`, `floor`, `ceil`, `assert`, `read_file`, `write_file`, `append_file`, `file_exists`, `file_size`, `is_file`, `is_dir`, `is_symlink`, `list_dir`, `glob`, `make_dir`, `remove_file`, `remove_dir`, `rename`, `copy_file`, `copy_dir_all`, `split`, `join`, `trim`, `starts_with`, `ends_with`, `replace`, `path_join`, `path_parent`, `path_name`, `path_stem`, `path_extension`, `path_is_absolute`.
- Basic file I/O (T-058, ADR-0026): `read_file` returns valid UTF-8 without NUL bytes, capped at 64 MiB; `write_file` creates/truncates and `append_file` creates/appends; `file_exists` is the non-failing path probe; paths use host privileges and the process working directory; there is no sandbox and writes are not atomic.
- File metadata probes (T-064, ADR-0032): `file_size` follows symbolic links and requires an existing regular file, reporting logical `st_size` and failing with `R0015`; `is_file` and `is_dir` follow symbolic links and return `false` when metadata cannot be read; `is_symlink` uses `lstat` and is `true` for file, directory, and dangling links. No metadata object, mode, owner, timestamp, ACL, inode, device, or recursive directory size is exposed, and no metadata is modified or preserved. Static non-`Str` arguments are `E0301`; dynamic interpreter values are `R0005`; dynamically typed native paths are `E0401`.
- Lexical glob expansion (T-065, ADR-0033): `glob(pattern)` splits on `/`, discards empty components, and treats a leading `/` as absolute. `*` matches zero or more Unicode scalar values, `?` matches one, `[a-z]`/`[!a-z]` classes match scalar values, and a whole-component `**` recurses without following symbolic links. Wildcards and `**` skip dot entries unless a component explicitly allows them; the base of `**` may itself be a link. Results are lexical spellings sorted by UTF-8 bytes and deduplicated. Malformed patterns and more than 1,024 components are `R0016`; listing or `**` `lstat` failures, non-UTF-8 entry names, more than 100,000 candidate paths, and `**` depth beyond 128 are `R0015`. Missing paths and non-directories produce no matches, as does a final literal `lstat` failure. Static non-`Str` arguments are `E0301`; dynamic interpreter values are `R0005`; dynamically typed native patterns are `E0401`. There is no escaping, brace/tilde expansion, case folding, normalization, sandbox, or streaming.
- Recursive directory copy (T-066, ADR-0034): `copy_dir_all(from, to)` requires an existing source directory and a new target whose parent exists; it rejects existing targets, empty/`.`/`..` target names, and targets equal to or inside the resolved source with `R0015`, never merges or overwrites, and leaves a partial target on failure. It follows links in the source path, rejects symbolic links and special files below the source root, copies regular-file bytes and raw entry names (including non-UTF-8 Unix names) without preserving permissions, ownership, timestamps, xattrs, ACLs, hard-link identity, or sparse layout, and caps trees at 100,000 entries and 128 directory levels below the source root. Static non-`Str` arguments are `E0301`; dynamic interpreter values are `R0005`; dynamically typed native paths are `E0401`. There is no recursive move, rollback, atomic staging, cancellation, or sandbox.
- Single-level directory operations (T-059, ADR-0027): `list_dir` returns names without `.`/`..`, sorted by UTF-8 bytes and rejected if any name is not valid UTF-8; `make_dir` creates one directory; `remove_file` removes files/symbolic links but not directories; `remove_dir` removes only empty directories; failures are fatal `R0015`.
- Rename and copy (T-061, ADR-0029): `rename` moves one file or directory and delegates overwrite/atomicity behavior to the host; `copy_file` copies regular-file bytes exactly (including NUL and invalid UTF-8) into a created/truncated target, preserves no metadata, and is not atomic; both fail with `R0015`. Source and target must be distinct, and a target that resolves to the source (including a symbolic-link or hard-link alias) is refused with `R0015` before the target is opened (T-089); the guard is best-effort and raceable. Recursive directory copy is provided separately by `copy_dir_all`.
- UTF-8 text builtins (T-060, ADR-0028): `split` is literal and preserves empty fields, or splits into Unicode scalar values for an empty separator; `join` requires `List[Str]`; `trim` removes exactly the Unicode `White_Space` set; `starts_with`/`ends_with` are byte-exact; `replace` is left-to-right and non-overlapping and rejects an empty pattern with `R0016`; there is no regex, case mapping, normalization, or grapheme-cluster API.
- Lexical path builtins (T-062, ADR-0030): `path_join`, `path_parent`, `path_name`, `path_stem`, `path_extension`, and `path_is_absolute` operate on POSIX-style `/` paths without filesystem access. They do not normalize repeated separators or `.`/`..`, do not enforce containment, preserve UTF-8 names, and treat a final dot as an extension separator only when it is neither the first nor the last byte. Static non-`Str` arguments are `E0301`; dynamic interpreter values are `R0005`. No new error code or dependency is introduced.

### Native backend (C11)
- `vantyx build <file.vtx>` lowers checked AST → typed IR → GNU C11 → executable via `clang` (override with `VANTYX_CC`), linked with libc/libm.
- `-o <path>` selects the output; default is the source stem.
- Supported native types: `Unit`, `Int`, `Float`, `Bool`, `Str`, `List[T]`, `Map[K, V]` for statically known type arguments, nominal structs, and nominal enums.
- Supported declarations/control flow: globals, functions, structs, enums, `match` statements and expressions with optional guards, `if`/`elif`/`else`, `while`, `for ... in range(...)`, `for x in list`, `for c in str`, `for k in map`, `range(...)` as a `List[Int]` value outside `for` loops, `return`, `break`, `continue`.
- Native enums (T-030, ADR-0012): heap-allocated tagged structs with a union of per-variant payloads. Construction, payload binding, wildcard arms, exhaustive matching, recursive and mutually recursive enums, enums in lists/maps/struct fields/globals/parameters/returns, structural display/equality/`type`, and cycle-safe payload handling all match the interpreter.
- Native scalar literal `match` (T-032): integer, negative-integer, string (`strcmp`), and boolean patterns, in both match statements and expressions; checked for type and exhaustiveness before lowering.
- Native match guards (T-033): guards on wildcard, variant, and literal patterns in both match forms. Payload-reading guards use a GNU C statement expression that tests the tag, declares the bindings, and evaluates the guard; side effects occur once per attempted arm.
- Native or-patterns (T-047/T-050, ADR-0021): top-level alternatives share one binding set; codegen emits a short-circuit alternative condition and initializes bindings from the matched alternative. Arm bodies and guards are emitted once, and differential tests compare interpreter/native stdout.
- Native nested payload patterns (T-048/T-049, ADR-0020): recursive `IrPattern` with absolute `IrFieldPath` bindings, short-circuit tag/literal tests, single-evaluation guards, and differential tests against the interpreter.
- Native lists (T-024, ADR-0009): literals, read/write indexing, `len`, `push`, `pop`, `contains`, iteration, display, aliasing, nested lists, lists of structs, list fields/parameters/returns/globals, bounds errors, and cycle-safe display.
- Native maps (T-027, ADR-0010, ADR-0016): literals, read/write/compound indexing, `len`, `contains`, `keys`, `values`, key iteration, display, aliasing, nested maps/lists/structs, structural keys, missing-key errors, and insertion-order preservation. Scalar keys (`Unit`, `Int`, `Float`, `Bool`, `Str`) use an open-addressing index with expected O(1) lookup at a 50% load factor; struct, enum, list, and map keys keep the linear structural-equality path.
- Native strings (T-025): UTF-8-aware `s[i]` returning a one-character `Str`, `for c in s`, and `len(s)`; bounds and negative-index errors match the interpreter (`R0003`).
- Native file and directory I/O (T-058/T-059, ADR-0026/ADR-0027): libc `fopen`/`fread`/`fwrite`/`fclose`, `stat`, `opendir`/`readdir`/`closedir`, `mkdir`, `unlink`, and `rmdir`; identical UTF-8/NUL validation, sorted listings, 64 MiB read cap, `R0015` failures, truncate/append behavior, and left-to-right argument evaluation as the interpreter; statically non-`Str` arguments fail with `E0301`, and dynamically typed (`Any`) native paths fail with `E0401`.
- Native rename and copy (T-061, ADR-0029): POSIX `rename`, `stat`/`S_ISREG`, and libc stream byte copying; identical byte output, target truncation, error classes, and ordered evaluation as the interpreter; dynamically typed paths fail with `E0401`. Metadata is not preserved and copies are not atomic.
- Native text builtins (T-060, ADR-0028): a shared UTF-8 decoder and Unicode `White_Space` table, literal split, ordered join, trim, prefix/suffix tests, and non-overlapping replacement; identical empty-field, empty-separator, empty-affix, and `R0016` behavior; multi-argument calls evaluate left to right; statically non-`Str` or non-`List[Str]` arguments fail with `E0301`, and dynamically typed (`Any`) native arguments fail with `E0401`.
- Native lexical paths (T-062, ADR-0030): byte-scanned C helpers for join, parent, name, stem, extension, and absolute detection; identical POSIX-style, non-normalizing behavior and ordered `path_join` evaluation as the interpreter; dynamically typed arguments fail with `E0401`; no filesystem access or new dependency.
- Native metadata probes (T-064, ADR-0032): POSIX `stat`/`lstat` helpers for `file_size`, `is_file`, `is_dir`, and `is_symlink`; identical follow-symlink rules, regular-file requirement for size, logical `st_size`, `R0015` size failures, and false-on-error predicates as the interpreter; dynamically typed paths fail with `E0401`; no metadata object.
- Native glob expansion (T-065, ADR-0033): POSIX `opendir`/`readdir`/`lstat` helpers and a component matcher over Unicode scalar values; identical grammar, hidden-entry rules, symlink non-traversal in `**`, byte sorting, deduplication, result/depth/component caps, and `R0016`/`R0015` error split as the interpreter; dynamically typed patterns fail with `E0401`.
- Native recursive copy (T-066, ADR-0034): `stat`/`realpath` source and target-parent resolution, component-boundary self-copy rejection, `opendir`/`readdir`/`lstat` traversal, raw-name and byte copying with `mkdir` and libc streams, inner-symlink and special-file rejection, and identical 100,000-entry / 128-depth caps and `R0015` failures as the interpreter; dynamically typed paths fail with `E0401`.
- Supported builtins: `print`, `len` (Str/List/Map), `range` (1–3 Int bounds, returning `List[Int]`), `push`, `pop`, `contains` (List/Str/Map), `keys`, `values`, `str`, `int`, `float`, `bool`, `type`, `abs`, `min`, `max`, `sqrt`, `floor`, `ceil`, `assert`, `read_file`, `write_file`, `append_file`, `file_exists`, `file_size`, `is_file`, `is_dir`, `is_symlink`, `list_dir`, `glob`, `make_dir`, `remove_file`, `remove_dir`, `rename`, `copy_file`, `copy_dir_all`, `split`, `join`, `trim`, `starts_with`, `ends_with`, `replace`, `path_join`, `path_parent`, `path_name`, `path_stem`, `path_extension`, `path_is_absolute`.
- Checked integer arithmetic, allocation growth, and the same runtime error codes as the interpreter for the supported subset.
- Structural equality for lists, maps, structs, and enums, including coinductive handling of cyclic values (matches the interpreter).
- Float display matches the interpreter's shortest round-trip decimal formatting, including inside collections.
- Imported functions, structs, and enums lower through the same IR and C backend as entry-file declarations (T-013); per-file source names are restored for diagnostics, and cross-file expression ids cannot collide.
- Native condition lowering (T-070, ADR-0036): `if`/`elif`/`while` conditions that lower to a GNU C statement expression (for example a call) are wrapped in one extra pair of parentheses; conditions that are already parenthesized comparisons keep their existing form, so clang does not emit `-Wparentheses-equality`.
- Native short-circuit logic (T-071, ADR-0036): `and`/`or` evaluate the right operand only when the left operand does not decide the result. Effectful right operands use a `bool` statement expression with a conditional expression; effect-free right operands use ordinary `&&`/`||`.
- Native output and float numeric determinism (T-079, ADR-0039): `print` evaluates every argument into a typed temporary before rendering or writing, so a failing argument leaves no partial stdout and later-argument mutations are visible in the whole line; float `min`/`max` implement the interpreter's explicit rule (single NaN yields the other operand; ties return the second operand) instead of C `fmin`/`fmax`.
- Native argument evaluation in `type` (T-080): the backend binds the argument to a typed temporary and discards it before yielding the static type name, so calls, mutation, nested output, and runtime errors inside `type(...)` agree with the interpreter instead of being skipped.
- Native left-to-right text arguments (T-060, T-081): multi-argument text builtins bind observable operands in source order; `contains` on strings now does the same instead of relying on unspecified C argument evaluation order, which GCC used right to left.
- Native constant-result operands (T-082/T-083): binary operators hoist both operands whenever either has effects, so `Unit ==`/`!=` still evaluate both sides in source order; interpolation exercises every expression, so a `Unit` expression renders as `()` only after its calls, output, mutation, or runtime errors occur.
- Native rejected-argument evaluation (T-084): `bool` evaluates its argument once before raising `R0007`, so side effects inside a statically rejected argument remain observable.
- 134 native tests compare interpreter vs native exit codes and stdout, or assert the checker's rejection of unsupported native constructs.
- Native result propagation (T-075, ADR-0038): a dedicated `Try` statement evaluates the operand once, compares the enum tag with the failure variant, returns the failure pointer directly (decrementing the call depth) on failure, and otherwise binds the success payload field to a fresh local; used for `let` initializers, plain assignments, and bare statements.
- All five `examples/` programs build and run natively with identical output.

### AI host foundation (T-037, T-038, T-039; ADR-0015)
- Zero third-party dependencies: the AI toolkit is part of the `vantyx` crate and links only the Rust standard library; remote HTTPS uses the system `curl` binary, and local endpoints use `std::net`.
- Strict JSON value, parser, and writer with depth, size, and duplicate-key limits; no `serde`.
- Provider trait with chat/model-list capabilities, stable `AI_E_*` errors, retryability, usage, finish reasons, text and image content parts, and mock/echo providers.
- OpenAI-compatible chat and model-list adapter; request mapping for messages, tools, response format, temperature, top-p, max tokens, and seed; bounded 8 MiB responses; timeouts; 401/429/5xx mapping; secret redaction.
- Streamed text chat (T-052, ADR-0023): `Provider::chat_stream` with a text-delta callback; OpenAI-compatible `stream: true` and `stream_options.include_usage`; `Accept: text/event-stream`; incremental SSE parsing with UTF-8 carry across chunks; final text/finish-reason/usage aggregation; usage estimation when omitted; error-frame redaction; streaming tool calls rejected with `AI_E_UNSUPPORTED`; loopback content-length, chunked, and close-delimited bodies; HTTPS through `curl --include --no-buffer`; CLI `--stream` with live flushes and `--json`/non-OpenAI rejection.
- Embedding provider interface (T-045, ADR-0017): typed batch requests with 128-input, 8 KiB-per-input, 32 KiB-per-request, and 1–4096-dimension limits; `Provider::embed` defaults to a stable unsupported error; `HashEmbeddingProvider` is a deterministic lexical feature-hash baseline, explicitly not a semantic model; `CachingEmbeddingProvider` is a bounded FIFO cache (1,024 entries / 4 MiB) keyed by model, dimensions, and text, with batch deduplication and clearable state; the OpenAI-compatible adapter posts to `/v1/embeddings`, sorts by index, validates counts and dimensions, and accounts usage.
- `vantyx ai embed` with offline `mock`/`hash`, OpenAI-compatible `openai`, `--dimensions`, stdin batches, JSON output, timeouts, and metrics; `echo` is rejected because it has no embeddings.
- Network policy: loopback HTTP is local; remote HTTPS requires `--allow-network` or `VANTYX_AI_ALLOW_NETWORK=1`; no implicit downloads.
- Deterministic budgets for steps, tool calls, tokens, and wall-clock time; cancellation flag; bounded agent loop with tool-result feedback.
- Token estimates are explicitly labelled as estimates, not model tokenizers.
- Embedding vector math (dot, norm, cosine, Euclidean, normalization) and an in-memory vector index with deletion.
- BM25 lexical retrieval with Unicode-aware tokenization and ranked hits.
- Local RAG foundation (T-046): bounded recursive ingestion of text, Markdown, and code with extension allowlists, hidden/symlink/VCS skipping, and file/count/size limits; stable line-cited chunks; provider-batched embeddings; strict-JSON index persistence with atomic replacement and 0600 permissions on Unix; BM25, cosine-semantic, and reciprocal-rank hybrid search with deterministic tie breaking; relative source-prefix filtering before top-k; query/top-k limits; and a retrieval-only evaluation harness reporting recall@k, precision@k, MRR, and per-query hits. It does not claim answer grounding.
- Incremental RAG updates (T-054, ADR-0024): `vantyx ai index --incremental` reuses a stored vector when the stable chunk id, provider, model, and dimensions match; embeds only new or changed chunks; prunes chunks absent from the current corpus scan; skips provider construction entirely when nothing changed; rejects lexical indexes and provider/model/dimension changes with actionable errors; and represents an empty semantic index as a valid version-1 file with zero chunks. Every update still walks and chunks the complete corpus.
- Diversity reranking (T-057, ADR-0025): `vantyx ai search --diverse` applies deterministic maximal-marginal-relevance selection over a bounded wider candidate pool, suppresses identical trimmed chunk text keeping the highest-ranked copy, uses cosine similarity over stored vectors or BM25-token Jaccard for lexical-only indexes, normalizes relevance by the best candidate score, and reports `rerank: mmr`; the default relevance weight is 0.7 and repeated runs are identical.
- `vantyx ai index`, `vantyx ai search`, and `vantyx ai eval` with offline `hash`/`mock` embeddings, OpenAI-compatible embeddings, `--json`, chunk controls, extension filters, and explicit lexical/semantic/hybrid modes.
- JSON Schema subset validation (type, required, properties, additionalProperties, items, min/max items, min/max length, pattern, enum, const, numeric bounds) with paths.
- Typed tool registry with capability sets, deny-by-default policy, path roots, approval modes, and read-only demo tools; denied capabilities return errors to the agent instead of executing.
- Opt-in JSONL metrics containing provider, model, operation, latency, usage, finish reason, error code, retry count, and tool name — never prompts, responses, arguments, or secrets.
- SSE parser with size and line limits, wired to streamed chat output (T-052).
- Offline model inspection (T-090, ADR-0041): `vantyx ai inspect <file>` parses bounded GGUF v2/v3 and Safetensors metadata and tensor directories, validates tensor ranges, known quantization block sizes, dtype sizes, alignment, exact byte lengths, and overlaps, and reports format, file size, streamed SHA-256, tensor and parameter counts, architecture/name/context/embedding/layer metadata, quantization, tokenizer model and token count, dtype histogram, and warnings; `--json` emits one stable object and `--metadata` prints every parsed entry. Unsupported or corrupt files are `AI_E_FORMAT`, I/O failures are `AI_E_IO`, and nothing is downloaded, loaded, modified, or executed.
- CLI: `vantyx ai providers`, `doctor`, `models`, `inspect`, `chat`, `extract`, `embed`, `index`, `search`, `eval`, and `tokens`; `--json`, `--metrics` for chat/extract/embed, `--system`, repeated `--message`, stdin prompts, and environment configuration.

### Performance baseline (T-022)
- Seven equivalent workloads (`arith_loop`, `enum_ops`, `fib`, `list_ops`, `map_ops`, `struct_ops`, `string_ops`) in Vantyx, Python, C, and Rust.
- The runner verifies identical stdout before timing, discards one warm-up, takes 5 measured runs, and records wall time, peak RSS, build time, and binary size.
- 2026-11-24 native medians vs interpreter: `arith_loop` 2.726 ms vs 684.518 ms, `enum_ops` 3.646 ms vs 687.079 ms, `fib` 1.795 ms vs 93.506 ms, `list_ops` 2.738 ms vs 226.563 ms, `map_ops` 1.781 ms vs 65.779 ms, `struct_ops` 5.348 ms vs 237.671 ms, `string_ops` 1.565 ms vs 36.897 ms.
- Native is in the same band as C/Rust on all seven workloads; absolute medians shift with machine load, so compare within a run. `enum_ops` puts heap-allocated native enums against stack-value C/Rust enums at 3.646 ms vs 3.766 ms and 4.529 ms, so the benchmark does not justify an enum representation rewrite. `string_ops` fell from 8.318 ms before T-055 to the 1.6–3.2 ms range after single-byte ASCII iteration stopped allocating per character. `map_ops` remains near C/Rust after the scalar-key hash index (1.781 ms vs C 1.355 ms and Rust 2.119 ms).
- Native string iteration and indexing return shared immutable buffers for single-byte ASCII characters from a static 128-entry table instead of allocating a 2-byte heap string per character (T-055); multi-byte UTF-8 characters still allocate. Native strings are never mutated in place, and the runtime is single-threaded.
- Raw results: `benchmarks/results/2026-11-22.{json,md}` and `benchmarks/results/2026-11-24.{json,md}`; methodology and caveats: `docs/benchmarks.md`. The enum backend is now benchmarked (T-056).

Language-level `from ai import Client` is blocked on async (T-017); the modules prerequisite (T-013) is now implemented.

- **Native backend subset** — `Any`, `List[Any]`, `Map[Any, *]`, `Any` enum payloads, dynamic `match` on `Any`, unsupported loop forms, and string index assignment are rejected with `E0401`/`E0306`; native strings, structs, list buffers, map buffers, map indexes, and enum values are leaked; no debug info. Scalar map keys use a hash index, but struct/enum/list/map keys remain O(n) and the fixed hash seed is not collision-resistant against adversarial keys (ADR-0016). Native enum layout and allocation policy are documented in ADR-0012.
- **Enums and pattern matching** — closed enums, payloads, exhaustive matching, `Any` matching, scalar literal patterns, nested payload patterns, top-level or-patterns, integer range patterns, and guards are implemented in the interpreter and native backend. Tuple patterns, range expressions, float/interpolated-string patterns, generic enums, and explicit discriminants are not implemented (ADR-0011, ADR-0019, ADR-0020, ADR-0021, ADR-0022).
- **Result-enum propagation** (T-075, ADR-0038): postfix `?` unwraps the first variant's single payload of a nominal two-variant enum, or returns the second variant unchanged from the enclosing function. It is accepted only as a whole `let` initializer, plain assignment value, or expression statement. The enclosing function must have an explicit return type equal to the operand's enum. Invalid placements, non-enum operands, enums with the wrong variant/field count, missing annotations, and mismatched return types are `E0319`. There is no built-in generic `Result`, error conversion, or expression-position propagation.
- **Match expression placement** — a match expression is block-shaped and must be the final element of its statement or arm. It cannot appear inside parentheses or brackets because newlines are suppressed there; that case now reports `E0101` with a targeted help message (T-031).
- **REPL** — persistent, error-recovering, and now has line editing, history, completion, and value echo (T-029). Remaining limits: earlier entries are replayed with output muted, so long sessions repeat work; redefining a name is an error; history recall is single-line only; completion covers top-level names, not fields or locals; non-TTY input falls back to canonical line input (ADR-0013).
- **Runtime type metadata** — collections do not retain element type arguments after construction; deep conformance is checked only at annotated boundaries.
- **Memory management** — interpreter reference counting leaks cycles; native allocations are intentionally leaked. No cycle collector yet (ADR-0005, ADR-0008, ADR-0009, ADR-0010, ADR-0012).

The largest open risks are intentional native leaks, O(n) structural-key map operations and a fixed hash seed for scalar keys, enum allocation cost (unmeasured), gradual `Any` eroding static guarantees, documentation drift, and host-privileged file I/O with no sandbox or atomic writes. The drift found on 2026-11-23 (T-030 implemented but still marked READY) is mitigated by the status-sync rules in `AGENTS.md` and the `spec-sync-auditor` subagent.
