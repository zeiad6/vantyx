## T-095 result

The shared schema subset now follows JSON Schema semantics where it previously
diverged:

- `required` applies only to objects.
- `check_schema` rejects empty `enum` and empty `allOf`.
- `anyOf` no longer returns early on a match; `additionalProperties`/`items`
  no longer return early for non-object/non-array values. Sibling keywords are
  always evaluated.
- `const`/`enum` use `json::value_eq`: mathematical number equality
  (`1 == 1.0`), order-independent objects, order-sensitive arrays, exact
  integer comparisons beyond `2^53`.
- `minimum`/`maximum` use `json::number_cmp` instead of `f64` conversion.
  `int_float_cmp`/`uint_float_cmp` reject the `2^63`/`2^64` boundaries
  explicitly because Rust float-to-integer casts saturate.
- `extract` preflights with `check_schema` and fails `AI_E_INVALID_REQUEST`
  with `extraction schema is invalid` before building a provider request.
- `ToolRegistry::call` preflights the declared parameter schema and fails
  `AI_E_SCHEMA` with `tool <name> has an invalid parameter schema`; the tool
  body never runs.
- `docs/decisions/ADR-0045-json-schema-conformance-and-preflight.md` records
  decisions, alternatives, and remaining subset limits.
