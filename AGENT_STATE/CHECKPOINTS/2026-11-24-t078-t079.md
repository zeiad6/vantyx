  `numeric_string_grammar_matches`, and expanded fuzzer numeric/error shapes.

### T-079 — Deterministic `print` and float `min`/`max`

- A targeted probe found that native `min`/`max` used C `fmin`/`fmax`
  (first operand on a signed-zero tie) while the interpreter returned the
  second, and that native `print` wrote each argument before evaluating the
  next.
- Both engines now implement one explicit float rule: a single NaN yields the
  other operand; a tie returns the second operand. The interpreter no longer
  relies on `f64::min`/`f64::max`; native no longer uses libm.
- `print` now evaluates all arguments into typed temporaries in order, then
  renders and writes the line. A failing argument leaves no partial stdout and
  later mutations are visible in the rendered line.
- Tests: e2e `float_min_max_ties_and_nan_are_stable` and
  `print_evaluates_every_argument_before_writing`; native
  `float_min_max_ties_match` and `print_evaluates_arguments_before_writing`;
  fuzzer numeric signed-zero/NaN cases and a failing `print` case.
- Specification §6/§11 and ADR-0039 document both rules.
