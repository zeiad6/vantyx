## Uncommitted and verified locally

### T-081 — Compiler-independent native `contains` argument order

- Native string `contains` emitted
  `vantyx_str_contains(haystack, needle)` with both operands inline. C leaves
  argument evaluation order unspecified: clang used left to right, GCC used
  right to left, and only GCC diverged from the interpreter for effectful
  arguments.
- Pre-fix GCC output was `eval needle`, `eval hay`, `["needle", "hay"]`; the
  interpreter produced `eval hay`, `eval needle`, `["hay", "needle"]`.
- `src/codegen_c.rs::builtin_expr` now binds both operands to `vantyx_str`
  temporaries in source order and calls the helper from a statement
  expression.
- Tests: extended native `text_builtins_evaluate_arguments_left_to_right` with
  `contains`, `starts_with`, and `ends_with`; new native
  `string_contains_argument_order_is_compiler_independent` builds and runs the
  probe with both clang and GCC.
- Specification §6 and §11 state the left-to-right rule for string
  `contains`.

### T-080 — Evaluate the argument of `type`

- `src/codegen_c.rs` binds the argument to a typed temporary, discards it, and
  yields the static type name, so nested calls, output, mutation, and runtime
  errors agree with the interpreter.
- Tests: e2e `type_evaluates_its_argument`, native
  `type_evaluates_arguments`, and fuzzer cases.

### T-079 — Deterministic `print` and float `min`/`max`

- Both engines evaluate all `print` arguments into temporaries, render them,
  then write one line; float `min`/`max` use one explicit rule (single NaN
  yields the other operand; ties return the second operand).
- ADR-0039 records the rationale; e2e/native tests and fuzzer cases cover both
  behaviors.

### T-078 — Strict numeric string conversion in the native runtime

- `int(text)`/`float(text)` trim Unicode whitespace and validate the exact
  interpreter grammar before calling `strtoll`/`strtod`; float `ERANGE` is
  ignored so overflow/underflow match Rust.
- The 28-form probe found 8 divergences before and 0 after.
