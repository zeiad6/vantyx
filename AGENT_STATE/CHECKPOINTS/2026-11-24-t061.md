# Checkpoint — 2026-11-24 — T-061 rename and file copy

## Scope

Added `rename` and `copy_file` builtins to the checker, interpreter, IR, and
native C backend. Both are fatal `R0015` operations. `copy_file` copies bytes
only and can copy NUL, invalid UTF-8, and high-bit data that `read_file`
rejects; it preserves no metadata and is not atomic. `rename` delegates
overwrite and atomicity behavior to the host.

## Implementation

- `src/checker.rs`: builtin registry plus `E0301` checks for two `Str` paths.
- `src/interp.rs`: `std::fs::rename`; `std::fs::File` + `std::io::copy` with a
  regular-file check for copies.
- `src/ir.rs`: rejects dynamically typed (`Any`) paths with `E0401`; static
  non-`Str` mismatches are `E0301` in the checker.
- `src/codegen_c.rs`: POSIX `rename`, `stat`/`S_ISREG`, and libc-stream
  byte-copy helpers; statement expressions enforce source-before-target
  evaluation.
- `docs/decisions/ADR-0029-rename-and-copy.md`: semantics and limits.

## Limits

No recursive copy/move, glob, metadata preservation, atomic copy, fsync,
progress reporting, or recoverable `Result`-based errors. Source and target must
be distinct; same-path copies can truncate the source. Rename overwrite and
atomicity are host-defined, and Windows native support remains unverified.
