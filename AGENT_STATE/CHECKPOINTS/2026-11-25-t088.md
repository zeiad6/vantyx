# Checkpoint 2026-11-25 — T-088 named constructor evaluation order

## Task

T-088 — Source-order evaluation of named struct-constructor arguments.

## Status

VERIFIED locally; commit, push, and CI pending. T-078 through T-087 remain
uncommitted in the same working tree.

## Defect

Named struct-constructor arguments are written in source order but stored in
declaration order. The native IR lowering reordered the lowered arguments
before code generation, so the emitted C call evaluated them in declaration
order. The interpreter evaluated them as written.

Probe:

```vantyx
struct Pair:
    left: Int
    right: Int

struct Triple:
    a: Int
    b: Int
    c: Int

fn note(label: Str, value: Int) -> Int:
    print(label)
    return value

let p = Pair(right=note("right", 2), left=note("left", 1))
let q = Triple(c=note("c", 3), a=note("a", 1), b=note("b", 2))
let r = Pair(note("first", 10), note("second", 20))
```

- Before: interpreter printed `right`, `left`, `c`, `a`, `b`; clang and GCC
  printed `left`, `right`, `a`, `b`, `c`.
- Positional constructors were already correct.

## Fix

- `src/ir.rs`: `IrExprKind::Construct` gains `eval_order`, a list of argument
  indices in source order while `args` remains in declaration order.
  `lower_constructor` records each named argument's declaration position and
  emits the identity order for positional calls.
- `src/codegen_c.rs`: new `construct_expr` evaluates effectful arguments into
  typed temporaries in `eval_order`, then calls the generated constructor with
  the temporaries in declaration order. Pure and identity-order constructors
  keep the ordinary `call_expr` path.
- `docs/language_specification.md` §5.5 states the evaluation-order rule.
