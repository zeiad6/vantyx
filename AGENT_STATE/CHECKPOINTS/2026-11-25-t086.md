## Defect

Native `path_stem` and `path_extension` searched only for a dot with at least
one byte after it. When the final dot was trailing, they fell back to an
earlier dot. The interpreter always takes the last dot and then rejects it
when it is first or last. A targeted 30-path probe found four divergences:

| Expression | Interpreter | Native before fix |
| --- | --- | --- |
| `path_stem("a/b..")` | `b..` | `b` |
| `path_extension("a/b..")` | `` | `.` |
| `path_stem("a/...")` | `...` | `.` |
| `path_extension("a/...")` | `` | `.` |

The divergence was silent: exit code and error behavior agreed.

Reproducer: `/tmp/opencode/audit/paths.vtx`.

## Fix

`src/codegen_c.rs` adds `vantyx_path_extension_dot`, which finds the final dot
from index `1` and returns no separator when it is absent or last. Both helpers
share it. This matches the interpreter's `rposition` plus
`dot > 0 && dot + 1 < len` rule and deliberately does not fall back to an
earlier dot.

  names with no diff.

## Specification

- ADR-0030 now states that when the final dot is not a separator, no earlier
  dot is considered.
- `docs/language_specification.md` states the same rule and gives `a..` as an
  example.
