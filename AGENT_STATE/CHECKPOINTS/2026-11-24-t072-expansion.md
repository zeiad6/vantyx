## Work

1. Expanded `tools/differential_fuzz.py` from three to eight program shapes:
   - scalar expressions and control flow (existing);
   - collections, structs, enums, and map keys (existing);
   - guarded/range/or-pattern matching (existing);
   - nested lists, maps, structs, and enums with aliasing and mutation;
   - typed functions with parameters, early returns, recursion, loops, and
     calls in conditions;
   - string escapes, interpolation, indexing, and UTF-8 builtins;
   - checked integer arithmetic, float formatting, and conversions;
   - runtime-error agreement for bounds, missing keys, division by zero,
     overflow, exact `int` conversion, `sqrt`, empty `pop`, and `assert`.
2. Found and fixed a coverage bug in the existing collection generator: it
   used `xs[-1]`, which is an invalid negative index, so every collection
   program failed at that statement and never exercised the remaining 20+
   statements. It now uses `xs[len(xs) - 1]`.
3. Removed empty `replace` patterns from generated expressions because they
   are runtime errors, and bounded `**` bases so generated programs do not
   overflow before reaching later statements.
4. Raised the CI differential-fuzz step from 50 to 80 iterations on seed 1.
5. Updated the fuzzer docstring, README test count (613), task/status/baseline
   records, and the historical requirements audit with T-070–T-072 rows.

## Decisions

- Keep every generated program runnable to completion unless it is the
  dedicated runtime-error shape. A program that stops at an early error has
  little differential value even when both engines agree.
- Keep the runtime-error shape because silent miscompilation on error paths is
  a P0 risk; it compares exit code and the stdout prefix, not diagnostic text.
- Keep the fuzzer standard-library-only and deterministic; no dependency was
  added.
- Do not add shrinking or sanitizer integration in this change; track them as
  follow-ups so the current expansion stays reviewable.

## Known limits and failures

- Eight shapes are not a proof of correctness. There is no shrinking, no
  sanitizer integration, and no coverage measurement.
- Error-path agreement covers exit codes and stdout before the failure, not
  diagnostic text or error codes.
- Native cases skip when no C compiler is installed.
