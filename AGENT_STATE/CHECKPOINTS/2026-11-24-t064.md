# Checkpoint — 2026-11-24 — T-064 file metadata probes

## Objective

Add read-only file metadata probes to the interpreter and native backend with
matching follow-symlink rules, no new dependency, and no metadata mutation:
`file_size`, `is_file`, `is_dir`, and `is_symlink`.

## Contract (ADR-0032)

- `file_size(Str) -> Int` follows symbolic links, requires an existing regular
  file, returns logical host `st_size`, and raises `R0015` for missing paths,
  dangling links, directories, other non-regular targets, permission or I/O
  failures, and sizes not representable as `Int`.
- `is_file(Str) -> Bool` and `is_dir(Str) -> Bool` follow symbolic links and
  return `false` whenever metadata cannot be read.
- `is_symlink(Str) -> Bool` uses `lstat` and returns `true` for a link to a
  file, a link to a directory, and a dangling link.
- Static non-`Str` arguments are `E0301`; dynamic interpreter values are
  `R0005`; dynamically typed native paths are `E0401`.
- No mode, owner, group, timestamp, ACL, extended attribute, inode, device,
  birthtime, or recursive directory size is exposed. No metadata is modified
  or preserved. Check-then-act races apply and the probes are not a sandbox.
- Native strings cannot contain NUL; the IR already rejects NUL-containing
  source with `E0401`. The interpreter rejects a NUL path with `R0015`.

## Implementation

- `src/checker.rs`: builtin registry, arity, `E0301` path checks, `Int`/`Bool`
  result types.
- `src/interp.rs`: `metadata` for size with regular-file and `i64` checks,
  `Path::is_file`/`is_dir` for follow-symlink predicates, and
  `symlink_metadata` for `is_symlink`.
- `src/ir.rs`: `Str` argument validation and result typing.
- `src/codegen_c.rs`: `vantyx_file_size` (`stat`, `S_ISREG`, `R0015`),
  `vantyx_is_file`/`vantyx_is_dir` (`stat` plus `S_ISREG`/`S_ISDIR`), and
  `vantyx_is_symlink` (`lstat` plus `S_ISLNK`).

  interpreter paths, and `E0401` for native `Any` paths.
