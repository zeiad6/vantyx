## Defect

Native `bool(value)` lowered a statically non-`Bool` argument to
`vantyx_bool_from_other(...)` without emitting `value`. The interpreter
evaluates the argument as an ordinary call argument and only then raises
`R0007`. A targeted probe found that `print(bool(side()))`, where
`fn side() -> Int` prints `side` and returns `1`, printed `side` in the
interpreter but not natively; the exit code and error agreed, so the lost side
effect was silent.

Reproducer: `/tmp/opencode/p35/bool.vtx`.

## Fix

`src/codegen_c.rs::builtin_expr`'s `bool` branch now binds the argument to a
typed temporary. A `Bool` argument yields the temporary; any other static type
emits `(void)temporary; vantyx_bool_from_other(...)` inside the same GNU
statement expression, so evaluation happens before the runtime error. This
mirrors the T-080 `type` fix and adds no runtime helper or syntax.

## Tests

- e2e `bool_evaluates_its_argument` checks `bool(flag())` output and then
  `bool(side())` printing `side` before exit `2` with `R0007`.
- native `bool_evaluates_its_argument` compares both engines on the same
  program.
- `tools/differential_fuzz.py::error_program` includes
  `print(bool(bool_side_int()))`, whose argument prints before the rejection.

## Specification

- The built-in table states that only `Bool` is accepted and that the argument
  is still evaluated first.
- §11 documents the native rejected-argument evaluation rule.
