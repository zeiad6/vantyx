## Uncommitted and verified locally

### T-080 — Evaluate the argument of `type`

- The native backend lowered `type(value)` to a static string constant and
  skipped `value`. A probe showed `type(print("x"))` losing the nested output,
  a mutating call never running, and `print(type(assert(false)))` printing
  `Unit` and exiting `0` while the interpreter raised `R0006`.
- `src/codegen_c.rs` now binds the argument to a typed temporary, discards it
  with `(void)`, and yields the static type name, evaluating exactly once.
- Tests: e2e `type_evaluates_its_argument`; native
  `type_evaluates_arguments`; fuzzer `functions_program` and `error_program`
  cases.
- Specification §6 and §11 document the evaluation rule.

### T-079 — Deterministic `print` and float `min`/`max`

- Both engines evaluate all `print` arguments into temporaries, render them,
  then write one line; float `min`/`max` use one explicit rule (single NaN
  yields the other operand; ties return the second operand).
- Tests: e2e `float_min_max_ties_and_nan_are_stable` and
  `print_evaluates_every_argument_before_writing`; native
  `float_min_max_ties_match` and `print_evaluates_arguments_before_writing`;
  fuzzer numeric/error cases.
- ADR-0039 records the rationale.

### T-078 — Strict numeric string conversion in the native runtime

- `int(text)`/`float(text)` trim Unicode whitespace and validate the exact
  interpreter grammar before calling `strtoll`/`strtod`; float `ERANGE` is
  ignored so overflow/underflow match Rust.
- The 28-form probe found 8 divergences before and 0 after.
