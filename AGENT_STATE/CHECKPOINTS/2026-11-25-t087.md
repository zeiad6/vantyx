# Checkpoint — T-087 lexical function scope

Date: 2026-11-25
Status: VERIFIED locally; commit, push, and CI pending
Branch: `main` at `1aba7ba` (working tree contains T-078 through T-087)

## Defect

The interpreter kept one flat scope stack and searched it from newest to
oldest. A user function pushed its frame onto the same stack, so name
resolution continued into every caller frame. A caller local with the same
name as a global therefore shadowed the global inside the callee. The checker
and native backend resolved such names to the global, so the interpreter was
the wrong engine.

The reproducer had three observable failures:

- `read_total()` returned the caller's local `100` instead of global `10`.
- `bump_total()` silently mutated the caller's local instead of the global.
- `bump_other()` raised `R0010` against an immutable caller binding instead of
  updating global `20` to `21`.

Pre-fix interpreter stdout was `100`, then exit `2`; native printed `10`,
`11`, `100`, `21`, `caller-immutable`.

## Fix

`src/interp.rs`:

- `Interpreter` gains `frame_base: usize`, the first scope belonging to the
  active call.
- `lookup` searches `scopes[frame_base..]` from newest to oldest, then root
  scope zero when `frame_base > 0`.
- `find_scope` applies the same rule and returns the absolute scope index.
- `call_user` saves the previous boundary, sets `frame_base = scopes.len()`
  before pushing the function scope, and restores it after the call, including
  on the error path.

No syntax, checker, IR, native backend, or dependency change was needed.
Specification §3.1 and §11 now state that a callee resolves names in its own
frame and the top-level bindings only. ADR-0040 records the decision and
rejects dynamic scoping.
