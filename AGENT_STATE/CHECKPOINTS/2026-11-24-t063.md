# Checkpoint — 2026-11-24 — T-063 recursive directory creation and removal

## Scope

Added `make_dir_all` and `remove_dir_all` to the checker, interpreter, IR, and
native C backend. Creation creates every missing parent, accepts an existing
directory or symlink to a directory, and treats an empty path as a no-op
success. Removal deletes a tree without confirming, unlinks symbolic links
instead of traversing them (including a root link), and trims direct trailing
separators before the root type check so `link/` is unlinked rather than
followed. Both use fatal `R0015`; dynamic interpreter values are `R0005`;
native dynamically typed paths are `E0401`.

## Implementation

- `src/checker.rs`: builtin registry and one-argument `E0301` checks for `Str`
  paths.
- `src/interp.rs`: `std::fs::create_dir_all`/`remove_dir_all` dispatch with
  trailing-separator root normalization.
- `src/ir.rs`: native type validation; dynamically typed paths fail with
  `E0401`.
- `src/codegen_c.rs`: `vantyx_make_dir_all`, `vantyx_remove_tree`,
  `vantyx_remove_dir_all`, and `vantyx_directory_error`; creation checks each
  component with directory confirmation, removal uses
  `lstat`/`opendir`/`readdir`/`unlink`/`rmdir`, and the root link check follows
  separator trimming.
- `docs/decisions/ADR-0031-recursive-directory-operations.md`: contract,
  symlink rules, failure modes, and limits.

## Limits

No confirmation, trash, dry run, rollback, atomic staging, depth limit,
entry-count limit, metadata preservation, globbing, traversal callback, sorted
recursive walk, or sandbox. A failed recursive removal can leave a partial
tree. Only direct trailing separators are trimmed before the root link check;
`link/.` and `link/..` can still traverse a symlinked directory and require
caller validation. Native recursion uses the C stack. Both operations are
subject to check-then-act races. Windows native support remains unverified.
